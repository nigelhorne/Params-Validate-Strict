   86: =head2 validate_strict
   87: 
   88: Validates a set of parameters against a schema.
   89: 
   90: This function takes two mandatory arguments:
   91: 
   92: =over 4
   93: 
   94: =item * C<schema> || C<members>
   95: 
   96: A reference to a hash that defines the validation rules for each parameter.
   97: The keys of the hash are the parameter names, and the values are either a string representing the parameter type or a reference to a hash containing more detailed rules.
   98: 
   99: As an alternative the schema may be supplied as an B<arrayref of parameter hashrefs>,
  100: where every element describes one parameter and carries a mandatory
  101: C<name> key:
  102: 
  103:   $schema = [
  104:     { name => 'username', type => 'string', min => 3, max => 50 },
  105:     { name => 'age',      type => 'integer', min => 0, max => 150 },
  106:     { name => 'role',     type => 'string', optional => 1, default => 'user' },
  107:   ];
  108: 
  109: The arrayref form is normalised to the standard hashref form before any further
  110: processing.  It is particularly useful when declaration order matters (e.g.
  111: for positional or mixed calling conventions used by some CPAN modules).  The
  112: C<name> key is consumed during normalisation and does not appear as a
  113: validation rule.
  114: 
  115: For some sort of compatibility with L<Data::Processor>,
  116: it is possible to wrap the schema within a hash like this:
  117: 
  118:   $schema = {
  119:     description => 'Describe what this schema does',
  120:     error_msg => 'An error message',
  121:     schema => {
  122:       # ... schema goes here
  123:     }
  124:   }
  125: 
  126: =item * C<args> || C<input>
  127: 
  128: A reference to a hash containing the parameters to be validated.
  129: The keys of the hash are the parameter names, and the values are the parameter values.
  130: 
  131: =back
  132: 
  133: It takes optional arguments:
  134: 
  135: =over 4
  136: 
  137: =item * C<description>
  138: 
  139: What the schema does,
  140: used in error messages.
  141: 
  142: =item * C<error_msg>
  143: 
  144: Overrides the default message when something doesn't validate.
  145: 
  146: =item * C<unknown_parameter_handler>
  147: 
  148: This parameter describes what to do when a parameter is given that is not in the schema of valid parameters.
  149: It must be one of C<die>, C<warn>, or C<ignore>.
  150: 
  151: It defaults to C<die> unless C<carp_on_warn> is given, in which case it defaults to C<warn>.
  152: 
  153: =item * C<logger>
  154: 
  155: A logging object that understands messages such as C<error> and C<warn>.
  156: 
  157: =item * C<custom_types>
  158: 
  159: A reference to a hash that defines reusable custom types.
  160: Custom types allow you to define validation rules once and reuse them throughout your schema,
  161: making your validation logic more maintainable and readable.
  162: 
  163: Each custom type is defined as a hash reference containing the same validation rules available for regular parameters
  164: (C<type>, C<min>, C<max>, C<matches>, C<memberof>, C<values>, C<enum>, C<notmemberof>, C<callback>, etc.).
  165: 
  166:   my $custom_types = {
  167:     email => {
  168:       type => 'string',
  169:       matches => qr/^[\w\.\-]+@[\w\.\-]+\.\w+$/,
  170:       error_msg => 'Invalid email address format'
  171:     }, phone => {
  172:       type => 'string',
  173:       matches => qr/^\+?[1-9]\d{1,14}$/,
  174:       min => 10,
  175:       max => 15
  176:     }, percentage => {
  177:       type => 'number',
  178:       min => 0,
  179:       max => 100
  180:     }, status => {
  181:       type => 'string',
  182:       memberof => ['draft', 'published', 'archived']
  183:     }
  184:   };
  185: 
  186:   my $schema = {
  187:     user_email => { type => 'email' },
  188:     contact_number => { type => 'phone', optional => 1 },
  189:     completion => { type => 'percentage' },
  190:     post_status => { type => 'status' }
  191:   };
  192: 
  193:   my $validated = validate_strict(
  194:     schema => $schema,
  195:     input => $input,
  196:     custom_types => $custom_types
  197:   );
  198: 
  199: Custom types can be extended or overridden in the schema by specifying additional constraints:
  200: 
  201:   my $schema = {
  202:     admin_username => {
  203:       type => 'username',  # Uses custom type definition
  204:       min => 5,            # Overrides custom type's min value
  205:       max => 15            # Overrides custom type's max value
  206:     }
  207:   };
  208: 
  209: Custom types work seamlessly with nested schema, optional parameters, and all other validation features.
  210: 
  211: =back
  212: 
  213: The schema can define the following rules for each parameter:
  214: 
  215: =over 4
  216: 
  217: =item * C<type>
  218: 
  219: The data type of the parameter.
  220: Valid types are C<string>, C<integer>, C<number>, C<float> C<boolean>, C<scalar>, C<scalarref>, C<stringref>, C<hashref>, C<arrayref>, C<object>, C<coderef> and C<void>.
  221: C<scalar> accepts any plain scalar value (string, number, boolean, etc.) but rejects references (arrayrefs, hashrefs, coderefs, objects).
  222: C<scalarref> accepts a reference to a scalar value (e.g. C<\$var>) but rejects plain scalars, arrayrefs, hashrefs, coderefs, and objects.
  223: C<stringref> accepts a reference to a scalar that contains a plain string (e.g. C<\$str>) and rejects plain scalars, references-to-references, arrayrefs, hashrefs, coderefs, and objects.
  224: C<void> asserts that the parameter value is C<undef> (the parameter represents a void return or absent output).
  225: When C<void> is used the schema must contain exactly one parameter.
  226: The C<min>/C<max> constraints apply to the B<length> (in characters) of the referenced string.
  227: All other string rules (C<matches>, C<nomatch>, C<memberof>, etc.) operate on the dereferenced string value.
  228: The validated return value is the dereferenced plain string.
  229: 
  230: A type can be an arrayref when a parameter could have different types (e.g. a string or an object).
  231: 
  232:   $schema = {
  233:     username => [
  234:       { type => 'string', min => 3, max => 50 },	# Name
  235:       { type => 'integer', 'min' => 1 },	# UID that isn't root
  236:     ]
  237:   };
  238: 
  239: As a shorthand, C<type> itself may be an arrayref of type name strings (a I<union type>)
  240: when all other constraints are shared between the alternatives:
  241: 
  242:   $schema = {
  243:     data => { type => ['string', 'arrayref'] },
  244:     id   => { type => ['string', 'integer'], optional => 1 },
  245:   };
  246: 
  247: This is equivalent to the full array-of-rules form but more concise.
  248: Every other key in the rule hash (C<optional>, C<min>, C<max>, C<matches>, etc.)
  249: is inherited by each candidate type and validated independently against it.
  250: Type names are tried left-to-right; the first match wins and its coercion
  251: (e.g. numeric types) is propagated back to the caller.
  252: If the value fails all candidate types, validation croaks with a message
  253: listing the union members.
  254: 
  255: =item * C<can>
  256: 
  257: The parameter must be an object that understands the method C<can>.
  258: C<can> can be a simple scalar string of a method name,
  259: or an arrayref of a list of method names, all of which must be supported by the object.
  260: 
  261:    $schema = {
  262:      gedcom => { type => object, can => 'get_individual' }
  263:    }
  264: 
  265: =item * C<isa>
  266: 
  267: The parameter must be an object of type C<isa>.
  268: 
  269: =item * C<memberof>
  270: 
  271: The parameter must be a member of the given arrayref.
  272: 
  273:   status => {
  274:     type => 'string',
  275:     memberof => ['draft', 'published', 'archived']
  276:   }
  277: 
  278:   priority => {
  279:     type => 'integer',
  280:     memberof => [1, 2, 3, 4, 5]
  281:   }
  282: 
  283: For string types, the comparison is case-sensitive by default. Use the C<case_sensitive>
  284: flag to control this behavior:
  285: 
  286:   # Case-sensitive (default) - must be exact match
  287:   code => {
  288:     type => 'string',
  289:     memberof => ['ABC', 'DEF', 'GHI']
  290:     # 'abc' will fail
  291:   }
  292: 
  293:   # Case-insensitive - any case accepted
  294:   code => {
  295:     type => 'string',
  296:     memberof => ['ABC', 'DEF', 'GHI'],
  297:     case_sensitive => 0
  298:     # 'abc', 'Abc', 'ABC' all pass, original case preserved
  299:   }
  300: 
  301: For numeric types (C<integer>, C<number>, C<float>), the comparison uses numeric
  302: equality (C<==> operator):
  303: 
  304:   rating => {
  305:     type => 'number',
  306:     memberof => [0.5, 1.0, 1.5, 2.0]
  307:   }
  308: 
  309: Note that C<memberof> cannot be combined with C<min> or C<max> constraints as they
  310: serve conflicting purposes - C<memberof> defines an explicit whitelist while C<min>/C<max>
  311: define ranges.
  312: 
  313: =item * C<enum>
  314: 
  315: Same as C<memberof>.
  316: 
  317: =item * C<values>
  318: 
  319: Same as C<memberof>.
  320: 
  321: =item * C<notmemberof>
  322: 
  323: The parameter must not be a member of the given arrayref (blacklist).
  324: This is the inverse of C<memberof>.
  325: 
  326:   username => {
  327:     type => 'string',
  328:     notmemberof => ['admin', 'root', 'system', 'administrator']
  329:   }
  330: 
  331:   port => {
  332:     type => 'integer',
  333:     notmemberof => [22, 23, 25, 80, 443]  # Reserved ports
  334:   }
  335: 
  336: Like C<memberof>, string comparisons are case-sensitive by default but can be controlled
  337: with the C<case_sensitive> flag:
  338: 
  339:   # Case-sensitive (default)
  340:   username => {
  341:     type => 'string',
  342:     notmemberof => ['Admin', 'Root']
  343:     # 'admin' would pass, 'Admin' would fail
  344:   }
  345: 
  346:   # Case-insensitive
  347:   username => {
  348:     type => 'string',
  349:     notmemberof => ['Admin', 'Root'],
  350:     case_sensitive => 0
  351:     # 'admin', 'ADMIN', 'Admin' all fail
  352:   }
  353: 
  354: The blacklist is checked after any C<transform> rules are applied, allowing you to
  355: normalize input before checking:
  356: 
  357:   username => {
  358:     type => 'string',
  359:     transform => sub { lc($_[0]) },  # Normalize to lowercase
  360:     notmemberof => ['admin', 'root', 'system']
  361:   }
  362: 
  363: C<notmemberof> can be combined with other validation rules:
  364: 
  365:   username => {
  366:     type => 'string',
  367:     notmemberof => ['admin', 'root', 'system'],
  368:     min => 3,
  369:     max => 20,
  370:     matches => qr/^[a-z0-9_]+$/
  371:   }
  372: 
  373: =item * C<case_sensitive>
  374: 
  375: A boolean value indicating whether string comparisons should be case-sensitive.
  376: This flag affects the C<memberof> and C<notmemberof> validation rules.
  377: The default value is C<1> (case-sensitive).
  378: 
  379: When set to C<0>, string comparisons are performed case-insensitively, allowing values
  380: with different casing to match. The original case of the input value is preserved in
  381: the validated output.
  382: 
  383:   # Case-sensitive (default)
  384:   status => {
  385:     type => 'string',
  386:     memberof => ['Draft', 'Published', 'Archived'] # Input 'draft' will fail - must match exact case
  387:   }
  388: 
  389:   # Case-insensitive
  390:   status => {
  391:     type => 'string',
  392:     memberof => ['Draft', 'Published', 'Archived'],
  393:     case_sensitive => 0 # Input 'draft', 'DRAFT', or 'DrAfT' will all pass
  394:   }
  395: 
  396:   country_code => {
  397:     type => 'string',
  398:     memberof => ['US', 'UK', 'CA', 'FR'],
  399:     case_sensitive => 0  # Accept 'us', 'US', 'Us', etc.
  400:   }
  401: 
  402: This flag has no effect on numeric types (C<integer>, C<number>, C<float>) as numbers
  403: do not have case.
  404: 
  405: =item * C<min>/C<minimum>
  406: 
  407: The minimum length (for strings in characters not bytes), value (for numbers) or number of keys (for hashrefs).
  408: 
  409: =item * C<max>
  410: 
  411: The maximum length (for strings in characters not bytes), value (for numbers) or number of keys (for hashrefs).
  412: 
  413: =item * C<matches>
  414: 
  415: A regular expression that the parameter value must match.
  416: Checks all members of arrayrefs.
  417: 
  418: =item * C<nomatch>
  419: 
  420: A regular expression that the parameter value must not match.
  421: Checks all members of arrayrefs.
  422: 
  423: =item * C<position>
  424: 
  425: For routines and methods that take positional args,
  426: this integer value defines which position the argument will be in.
  427: If this is set for all arguments,
  428: C<validate_strict> will return a reference to an array, rather than a reference to a hash.
  429: 
  430: =item * C<regex>
  431: 
  432: Synonym of matches
  433: 
  434: =item * C<description>
  435: 
  436: The description of the rule
  437: 
  438: =item * C<callback>
  439: 
  440: A code reference to a subroutine that performs custom validation logic.
  441: The subroutine should accept the parameter value, the argument list and the schema as arguments and return true if the value is valid, false otherwise.
  442: 
  443: Use this to test more complex examples:
  444: 
  445:   my $schema = {
  446:     even_number => {
  447:       type => 'integer',
  448:       callback => sub { $_[0] % 2 == 0 }
  449:   };
  450: 
  451:   # Specify the arguments for a routine which has a second, optional argument, which, if given, must be less than or equal to the first
  452:   my $schema = {
  453:     first => {
  454:       type => 'integer'
  455:     }, second => {
  456:       type => 'integer',
  457:       optional => 1,
  458:       callback => sub {
  459:         my($value, $args) = @_;
  460: 	# The 'defined' is needed in case 'second' is evaluated before 'first'
  461: 	return (defined($args->{first}) && $value <= $args->{first}) ? 1 : 0
  462:       }
  463:     }
  464:   };
  465: 
  466: =item * C<optional>
  467: 
  468: A boolean value indicating whether the parameter is optional.
  469: If true, the parameter is not required.
  470: If false or omitted, the parameter is required.
  471: 
  472: It can be a reference to a code snippet that will return true or false,
  473: to determine if the parameter is optional or not.
  474: The code will be called with two arguments: the value of the parameter and hash ref of all parameters:
  475: 
  476:   my $schema = {
  477:     optional_field => {
  478:       type => 'string',
  479:       optional => sub {
  480:         my ($value, $all_params) = @_;
  481:         return $all_params->{make_optional} ? 1 : 0;
  482:       }
  483:     },
  484:     make_optional => { type => 'boolean' }
  485:   };
  486: 
  487:   my $result = validate_strict(schema => $schema, input => { make_optional => 1 });
  488: 
  489: If the parameter is not optional, it can be passed an undef value, which will not flag an error.
  490: This is by design.
  491: So this will not say that the required parameter 's' is missing:
  492: 
  493:     validate_strict(
  494:         schema => { s => { type => 'string' } },
  495:         input  => { s => undef },
  496:     );
  497: 
  498: =item * C<default>
  499: 
  500: Populate missing optional parameters with the specified value.
  501: Note that this value is not validated.
  502: 
  503:   username => {
  504:     type => 'string',
  505:     optional => 1,
  506:     default => 'guest'
  507:   }
  508: 
  509: =item * C<element_type>
  510: 
  511: Extends the validation to individual elements of arrays.
  512: 
  513:   tags => {
  514:     type => 'arrayref',
  515:     element_type => 'number',	# Float means the same
  516:     min => 1,	# this is the length of the array, not the min value for each of the numbers. For that, add a C<schema> rule
  517:     max => 5
  518:   }
  519: 
  520: =item * C<error_msg>
  521: 
  522: The custom error message to be used in the event of a validation failure.
  523: 
  524:   age => {
  525:     type => 'integer',
  526:     min => 18,
  527:     error_msg => 'You must be at least 18 years old'
  528:   }
  529: 
  530: =item * C<nullable>
  531: 
  532: Like optional,
  533: though this cannot be a coderef,
  534: only a flag.
  535: 
  536: =item * C<schema>
  537: 
  538: You can validate nested hashrefs and arrayrefs using the C<schema> property:
  539: 
  540:     my $schema = {
  541:         user => {	# 'user' is a hashref
  542:             type => 'hashref',
  543:             schema => {	# Specify what the elements of the hash should be
  544:                 name => { type => 'string' },
  545:                 age => { type => 'integer', min => 0 },
  546:                 hobbies => {	# 'hobbies' is an array ref that this user has
  547:                     type => 'arrayref',
  548:                     schema => { type => 'string' }, # Validate each hobby
  549:                     min => 1 # At least one hobby
  550:                 }
  551:             }
  552:         }, metadata => {
  553:             type => 'hashref',
  554:             schema => {
  555:                 created => { type => 'string' },
  556:                 tags => {
  557:                     type => 'arrayref',
  558:                     schema => {
  559:                         type => 'string',
  560:                         matches => qr/^[a-z]+$/	# Or you can say matches => '^[a-z]+$'
  561:                     }
  562:                 }
  563:             }
  564:         }
  565:     };
  566: 
  567: =item * C<validate>
  568: 
  569: A snippet of code that validates the input.
  570: It's passed the input arguments,
  571: and return a string containing a reason for rejection,
  572: or undef if it's allowed.
  573: 
  574:     my $schema = {
  575:       user => {
  576:         type => 'string',
  577: 	validate => sub {
  578: 	  if($_[0]->{'password'} eq 'bar') {
  579: 	    return undef;
  580: 	  }
  581: 	  return 'Invalid password, try again';
  582: 	}
  583:       }, password => {
  584:          type => 'string'
  585:       }
  586:     };

  588: =item * C<transform>
  589: 
  590: A code reference to a subroutine that transforms/sanitizes the parameter value before validation.
  591: The subroutine should accept the parameter value as an argument and return the transformed value.
  592: The transformation is applied before any validation rules are checked, allowing you to normalize
  593: or clean data before it is validated.
  594: 
  595: Common use cases include trimming whitespace, normalizing case, formatting phone numbers,
  596: sanitizing user input, and converting between data formats.
  597: 
  598:   # Simple string transformations
  599:   username => {
  600:     type => 'string',
  601:     transform => sub { lc(trim($_[0])) },  # lowercase and trim
  602:     matches => qr/^[a-z0-9_]+$/
  603:   }
  604: 
  605:   email => {
  606:     type => 'string',
  607:     transform => sub { lc(trim($_[0])) },  # normalize email
  608:     matches => qr/^[\w\.\-]+@[\w\.\-]+\.\w+$/
  609:   }
  610: 
  611:   # Array transformations
  612:   tags => {
  613:     type => 'arrayref',
  614:     transform => sub { [map { lc($_) } @{$_[0]}] },  # lowercase all elements
  615:     element_type => 'string'
  616:   }
  617: 
  618:   keywords => {
  619:     type => 'arrayref',
  620:     transform => sub {
  621:       my @arr = map { lc(trim($_)) } @{$_[0]};
  622:       my %seen;
  623:       return [grep { !$seen{$_}++ } @arr];  # remove duplicates
  624:     }
  625:   }
  626: 
  627:   # Numeric transformations

  706: =item * C<cross_validation>
  707: 
  708: A reference to a hash that defines validation rules that depend on more than one parameter.
  709: Cross-field validations are performed after all individual parameter validations have passed,
  710: allowing you to enforce business logic that requires checking relationships between different fields.
  711: 
  712: Each cross-validation rule is a key-value pair where the key is a descriptive name for the validation
  713: and the value is a code reference that accepts a hash reference of all validated parameters.
  714: The subroutine should return C<undef> if the validation passes, or an error message string if it fails.
  715: 
  716:   my $schema = {
  717:     password => { type => 'string', min => 8 },
  718:     password_confirm => { type => 'string' }
  719:   };
  720: 
  721:   my $cross_validation = {
  722:     passwords_match => sub {
  723:       my $params = shift;
  724:       return $params->{password} eq $params->{password_confirm}
  725:         ? undef : "Passwords don't match";
  726:     }
  727:   };
  728: 
  729:   my $validated = validate_strict(
  730:     schema => $schema,
  731:     input => $input,
  732:     cross_validation => $cross_validation
  733:   );
  734: 
  735: Common use cases include password confirmation, date range validation, numeric comparisons,
  736: and conditional requirements:
  737: 
  738:   # Date range validation
  739:   my $cross_validation = {
  740:     date_range_valid => sub {
  741:       my $params = shift;
  742:       return $params->{start_date} le $params->{end_date}
  743:         ? undef : "Start date must be before or equal to end date";
  744:     }
  745:   };
  746: 
  747:   # Price range validation
  748:   my $cross_validation = {
  749:     price_range_valid => sub {
  750:       my $params = shift;
  751:       return $params->{min_price} <= $params->{max_price}
  752:         ? undef : "Minimum price must be less than or equal to maximum price";
  753:     }
  754:   };
  755: 
  756:   # Conditional required field
  757:   my $cross_validation = {
  758:     address_required_for_delivery => sub {
  759:       my $params = shift;
  760:       if ($params->{shipping_method} eq 'delivery' && !$params->{delivery_address}) {
  761:         return "Delivery address is required when shipping method is 'delivery'";
  762:       }
  763:       return undef;
  764:     }
  765:   };
  766: 
  767: Multiple cross-validations can be defined in the same hash, and they are all checked in order.
  768: If any cross-validation fails, the function will C<croak> with the error message returned by the validation:
  769: 
  770:   my $cross_validation = {
  771:     passwords_match => sub {
  772:       my $params = shift;
  773:       return $params->{password} eq $params->{password_confirm}

  778:       return $params->{email} eq $params->{email_confirm}

  788:   };

  791: so you can rely on the data being in the correct format and type:

  793:   my $schema = {

  836: =item * C<relationships>
  837: 
  838: A reference to an array that defines validation rules based on relationships between parameters.
  839: Relationship validations are performed after all individual parameter validations have passed,
  840: but before cross-validations.
  841: 
  842: Each relationship is a hash reference with a C<type> field and additional fields depending on the type:
  843: 
  844: =over 4
  845: 
  846: =item * B<mutually_exclusive>
  847: 
  848: Parameters that cannot be specified together.
  849: 
  850:   relationships => [
  851:     {
  852:       type => 'mutually_exclusive',
  853:       params => ['file', 'content'],
  854:       description => 'Cannot specify both file and content'
  855:     }
  856:   ]
  857: 
  858: =item * B<required_group>
  859: 
  860: At least one parameter from the group must be specified.
  861: 
  862:   relationships => [
  863:     {
  864:       type => 'required_group',
  865:       params => ['id', 'name'],
  866:       logic => 'or',
  867:       description => 'Must specify either id or name'
  868:     }
  869:   ]
  870: 
  871: =item * B<conditional_requirement>
  872: 
  873: If one parameter is specified, another becomes required.
  874: 
  875:   relationships => [
  876:     {
  877:       type => 'conditional_requirement',
  878:       if => 'async',
  879:       then_required => 'callback',
  880:       description => 'When async is specified, callback is required'
  881:     }
  882:   ]
  883: 
  884: =item * B<dependency>
  885: 
  886: One parameter requires another to be present.
  887: 
  888:   relationships => [
  889:     {
  890:       type => 'dependency',
  891:       param => 'port',
  892:       requires => 'host',
  893:       description => 'port requires host to be specified'
  894:     }
  895:   ]
  896: 
  897: =item * B<value_constraint>
  898: 
  899: Specific value requirements between parameters.
  900: 
  901:   relationships => [
  902:     {
  903:       type => 'value_constraint',
  904:       if => 'ssl',
  905:       then => 'port',
  906:       operator => '==',
  907:       value => 443,
  908:       description => 'When ssl is specified, port must equal 443'
  909:     }
  910:   ]
  911: 
  912: =item * B<value_conditional>
  913: 
  914: Parameter required when another has a specific value.
  915: 
  916:   relationships => [
  917:     {
  918:       type => 'value_conditional',
  919:       if => 'mode',
  920:       equals => 'secure',
  921:       then_required => 'key',
  922:       description => "When mode equals 'secure', key is required"
  923:     }
  924:   ]
  925: 
  926: =back
  927: 
  928: If a parameter is optional and its value is C<undef>,
  929: validation will be skipped for that parameter.
  930: 
  931: If the validation fails, the function will C<croak> with an error message describing the validation failure.
  932: 
  933: If the validation is successful, the function will return a reference to a new hash containing the validated and (where applicable) coerced parameters.  Integer and number parameters will be coerced to their respective types.
  934: 
  935: The C<description> field is optional but recommended for clearer error messages.
  936: 
  937: =back
